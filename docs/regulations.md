## 1. 開発・実装で必ず守ること（違反は失格・審査対象外になりうる）

| ルール | 内容 | 確認するタイミング |
|---|---|---|
| カテゴリ | 医療・福祉／観光／**教育**／エンターテインメント／クリエイティブのどれか．本チームは**教育** | 機能の追加・方針変更のとき |
| テーマ | **"Own the Why, Build with Intent."**．AI の提案を鵜呑みにせず，案を比べて「なぜ選んだか」を自分の言葉で語る | 技術選定・PR を書くとき |
| 実行基盤 | 次の**1つ以上**でアプリを動かす: App Engine／Compute Engine／GKE／**Cloud Run**／**Firebase App Hosting**／**Firebase Hosting** | デプロイ構成を決める・変えるとき |
| メインの技術 | プロダクトの中核は **Google 技術**．AI コーディング支援ツール（Claude Code など）を開発に使うのは可 | 依存ライブラリ・API を選ぶとき |
| 他社 AI | プロダクト内で他社の LLM API を使うのは禁止ではないが，「Google 技術の活用」では評価されない．**他社 AI ツールが前面に出ているもの・メインのものは審査対象外**．デモ・ピッチで他社製品を前に出さない | AI 機能の実装・デモ・スライド作成のとき |
| 秘密情報 | API キー・秘密情報をリポジトリにコミットしない（審査「安全性」にも関わる） | コミット・PR のたび |
| 著作物 | 使った素材・ライブラリ・データの出典とライセンスを「著作物利用シート」で提出する | ライブラリ・画像・フォント・データを追加したとき |
| 開発開始前の制限 | 11/5 10:00 より前に書いたプロダクトのコード・IaC・CI/CD・フレームワーク初期化は使えない．**PoC のコードを本番へコピー・流用するのも禁止** | `poc/` のコードを本番に持ち込みたくなったとき |
| デモ動画 | **偽装は審査対象外**．事前処理済みのデータを見せるなら，偽装と見なされない範囲で正直に示す | デモ動画の撮影・編集のとき |
| 行動規範 | GDG のコミュニティガイドラインを守る | ― |

## 3. 審査基準（8項目 × 0〜3点 = 24点満点）

| # | 観点 | 項目 |
|---|---|---|
| 1-a | Google 技術の活用 | Google 技術がプロダクトの中核で有効に機能しているか |
| 1-b | 〃 | 目的・要件に対して，Google 技術を選んだ理由が合理的かつ具体的に説明されているか |
| 2-a | プロダクトの完成度 | 課題解決に必要な操作が一連の流れとして動くか |
| 2-b | 〃 | 対象ユーザーが目的を達成できる UI・UX か |
| 2-c | 〃 | 安全性・拡張性・保守性を見据えた設計か |
| 3-a | 社会課題への解決力 | 解決する課題が具体的かつ明確か |
| 3-b | 〃 | 機能や仕組みが実際の課題解決に有効か |
| 4-a | ピッチ | デモ・話の構成が分かりやすく，インパクトがあるか |

**採点外だが必須記入**（未記入は「必須項目の不足」で審査対象外になりうる）
- AI をどの場面でどう使ったか，なぜその場面か → `docs/ai-usage/issue-<Issue番号>.md` に記録する（過去分は `docs/ai-usage.md`）
- 開発を通して何を得て，どれだけ成長したか

**審査対象外になるもの（スライドに挙がっている例）**: デモ動画の偽装／他社 AI ツールが前面に出ている／テーマ・カテゴリ外／不適切な内容／ルール違反／必須項目の不足／Google Cloud の実行基盤を使っていない

**審査の流れ**: 全チーム提出 → 事前審査（参加20チーム超の会場は上位約20チームがピッチへ）→ Regional Day はピッチ中心に採点 → 上位を審査員が協議．Demo Day では Regional の点数は持ち越さず，1チーム6分（デモ・発表5分＋質疑1分），**Demo-first**（何を・なぜ作ったか → デモ）．

## Claude Code 向けチェックリスト

作業の前後で，該当するものを確かめる．当てはまる懸念があれば，作業を進める前に人間に伝える．

- [ ] 新しい依存ライブラリ・API・素材を足した → 著作物利用シートに載せる必要があることを人間に伝えたか
- [ ] AI 機能を実装した → 中核が Google 技術（Gemini / Vertex AI など）か．他社 LLM を前面に出していないか
- [ ] デプロイ構成を変えた → 実行基盤（Cloud Run / Firebase Hosting など）を1つ以上使い続けているか
- [ ] コミットする → API キー・サービスアカウント鍵・`.env` が入っていないか
- [ ] `poc/` のコードを本番に使いたい → 11/5 10:00 より前に書いたものではないか（前なら流用禁止）
- [ ] 技術選定・方針の判断をした → `docs/decisions/issue-<Issue番号>-短い説明.md` に「選んだ理由と捨てた案」を残したか（審査 1-b）
- [ ] AI の使い方で特筆すべきことがあった → `docs/ai-usage/issue-<Issue番号>.md` に1行足したか（必須記入）
- [ ] デモ用のデータ・動画を作る → 偽装に見えないか．教科書の問題文など他人の著作物を使っていないか
