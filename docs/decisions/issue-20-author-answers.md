# AI の問いかけへの本人の理由は，問い1つにつき1ドキュメントで `comparisons/{uidA}_{uidB}/answers/{side}_{stepId}` に保存し，本人だけが書けて参加者全員が読める（2026-11-08）

- 決めたこと:
  - Firestore のデータ構造（共有の契約．012・015 の `comparisons` の下に足す）:
    ```
    problems/{problemId}/comparisons/{uidA}_{uidB}/answers/{side}_{stepId}   ← 例: a_s1．問い（015 の questions の side と stepId）1つに1つ
      uid: string          ← 書いた本人．side が a なら uids[0]，b なら uids[1]
      side: 'a' | 'b'
      stepId: string
      text: string         ← 1〜1000字．本人が書いた理由
      updatedAt: Timestamp ← 書いた・書き直した時刻（request.time）
    ```
  - ルール（`firebase/firestore.rules`．テストは `firebase/test/rules.test.ts`）:
    - 読む: 全員が提出したあとの参加者（`canSeeOthers()`．`comparisons` と同じ）
    - 書く・書き直す・消す: 全員が提出したあと，対応関係が `done` で，`uid` が自分かつその side の本人で，ドキュメント ID が `{side}_{stepId}` のときだけ．項目はちょうど上の5つ，`text` は1〜1000字，`updatedAt` は `request.time`
    - その stepId に本当に問いが付いているかはルールでは確かめない（`questions` は map の配列で，ルールでは一部の項目で探せない）．画面は問いのあるステップにしか欄を出さない．余計に書けても本人の理由が1つ増えるだけ
  - 画面: 分岐点の図（`PairDiagram`）で，問いのあるステップの下に「AI の問いかけ」とその文を出す．自分の側なら理由を書く欄と保存ボタン（保存後は書き直す・消す），相手の側なら本人の理由か「まだ答えていません」を出す（`QuestionAnswer.tsx`）
    - 分岐点の問いは開いて出し，`missing_why` の問いは図が長くならないよう `<details>` でたたむ（理由が書かれていれば最初から開く．#60 の申し送り．PR #62 のレビューで指摘された）
  - `steps/{uid}` の `why`（`by: "author"`）には書かない
- 理由:
  - 問いごとにしたのは，分岐点の問い（branch）が「誰と比べたか」で変わり，3人以上だと同じステップに組ごとの別の問いが付くから（015）．問いが組ごとのドキュメントにあるので，その下に置けば対応がそのまま分かる
  - 参加者全員に見せるのは，本人の理由を材料に問い合うのがプロダクトの目的だから．全員が提出したあとなので，答えを写す心配はない（人が選んだ）
  - 書けるのを `done` のあとだけにしたのは，問いが無いうちに書く入口は無く，`processing` 中に組が作り直されると問いと答えがずれるから
  - 1ドキュメントにしたのは，ルールで「自分の側だけ」「項目と長さ」を確かめやすく，#21 で返信などを足すときもこの単位につなげやすいから
- 捨てた案とその理由:
  - `steps/{uid}.thoughtSteps.steps[i].why` に `by: "author"` で書く: スキーマの形をそのまま使えるが，ルールで「why 以外を変えていない」を配列全体について確かめられず，本人がステップ（what や元の場所）まで書き換えられてしまう．組ごとの分岐点の問いへの答えも1つにまとまってしまう
  - `problems/{problemId}/answers/{uid}` に stepId を鍵にした map で1人1つ: ルールは短いが，組ごとの分岐点の問いを区別できず，map の中身（長さ・項目）をルールで確かめにくい
- 承知のうえの弱さ:
  - 本人の理由は，思考ステップ一覧（`StepList`）の「なぜ」には出ない．分岐点の図の中だけ．必要なら別の Issue で合わせて出す
  - 3人以上だと，`missing_why` の問いへの理由も組ごとに分かれる．`missing_why` は誰と比べたかに依らない問いだが，答えは `comparisons/{組}/answers` に入るので，A が A・B の図で書いた理由は A・C の図には出ない．デモは2人なので今は困らない（PR #62 のレビューで指摘された）
  - 本番では，`answers` の `match` を含むルールを Hosting と同時か先に出す．ルールが無いと理由を読めない．そのときも分岐点の図は出し，問いの欄だけ隠す（PR #62 のレビューで指摘された）
  - `post_quote`（AI が投稿から抜き出した本人の言葉）を本人が承認・削除する UI はこの Issue では作っていない（`StepList` のコメントで #20 としていた部分）
