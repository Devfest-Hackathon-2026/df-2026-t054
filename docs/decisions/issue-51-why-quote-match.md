# why の引用は，プロンプトで「transcript と同じ書き方で写す」と指示したうえで，照合の前に書き方だけをそろえる（2026-11-08）

- 決めたこと:
  - 両方やる．`server/src/steps.ts` の `COMMON_RULES` に「why.text は transcript の一部を1文字も変えずに写す（`$`・`\sqrt{2}`・記号・句読点も同じにし，`√2` のように書き換えない）」を足し，照合（`server/src/quoteMatch.ts` の `findQuote`）でも書き方の違いをそろえる
  - そろえるのは表記だけ: `$`・波括弧・空白・句読点（`。．.、，,・！？「」『』`）を無視し，全角と半角を NFKC でそろえ，LaTeX のコマンドを記号に直す（`\sqrt` → `√`，`\leftarrow` → `←`，`\le` → `≤` など．表に無いコマンドは名前のまま比べる）．`\left`・`\right`・`\quad`・`\,` などの見た目だけのコマンドは無視する
  - そろえたあとで「そのまま含まれる」かを見る．通ったら，`why.text` を **transcript の該当部分（元の書き方のまま）** に置き換えて保存する．置き換えたことは warnings に残す
  - そろえたあとで 2 文字未満になる引用（句読点だけ・`$x$` だけなど）は通さない
- 理由:
  - #9 では，同じモデル・同じプロンプトでも回によって 0〜3 か所しか通らなかった．プロンプトの指示は守られるとは限らない（#8 で `const` が守られなかったのと同じ）ので，指示だけでは減り方が読めない．逆に照合だけだと，Gemini が書き方を変える理由（`√2` の方が読みやすい）がそのまま残り，表に無い書き方で落ち続ける
  - 照合が比べるのは「文字の並び」のままで，無視するのは意味を持たない記号だけにした．言い換え（「も」→「と」），理由の付け足し（「〜から」），読み違え（「√2」→「根号」），間を飛ばした引用は，どれも 1 文字以上違うので通らない（`server/test/quoteMatch.test.ts`）．設計原則「AI が言い換えた・補った理由は通さない」を，照合を緩めたあとも同じ強さで守れる
  - `why.text` を transcript の該当部分に置き換えるのは，契約（`shared/schema/README.md`）の「`why.text` が `transcript` にそのまま含まれる」を保存する値で満たすため．契約の文言は変えずに済み，画面（`web/src/StepList.tsx`）でも引用と書き起こしが同じ書き方で並ぶ
  - 切り出す範囲は「照合した最初の文字から最後の文字まで」で，端が `$…$` の数式の途中にあれば，その数式の `$` まで広げる（`√2も分数も…` で通ると `$\leftarrow \sqrt{2}$ も分数も…` になる）．広げないと `\sqrt{2}$ も…` のように `$` が片方だけ残り，画面にそのまま出る（PR #86 のレビューで指摘）．広げた分も transcript の文字なので，引用だけという原則は変わらない．`\$`（記号のドル）は区切りとして数えない
- 捨てた案とその理由:
  - プロンプトだけで直す: 守られるか分からず，#9 のように回ごとにばらつく
  - 照合だけで直す: 表に無い書き方（新しい記号など）では落ち続ける．プロンプトで書き方を揃えさせれば，照合で拾う必要がある違いそのものが減る
  - `why.text` を Gemini が返したまま保存する（`√2` の方が読みやすい）: 契約の「そのまま含まれる」を満たさなくなり，契約の変更（単独の PR）が要る
  - 編集距離などのあいまいな一致にする: 1〜2 文字の言い換え（「も」→「と」，「から」の付け足し）まで通ってしまい，AI が補った理由を通さないという原則が崩れる
  - LaTeX の構造まで解釈して比べる（`\frac{1}{2}` と `1/2` を同じにする など）: 手間のわりに #9 で落ちた例に無く，波括弧を無視するだけで `\sqrt{2}` と `√2` は一致する
- 手書きの答案で確かめた結果（2026-11-08，Vertex AI，`gemini-3.8-flash`，#9 と同じ手書き 2 枚・画素を回転済み，inline で 3 回）:
  - 本番のプロンプト・応答スキーマ・`normalizeSteps` を通し，同じ返り値で前の照合（そのまま含まれるか）と新しい照合の両方を数えた（確認用のスクリプトはコミットしていない）

    | 回 | 処理時間 | ステップ | Gemini が返した why | 前の照合で残る | 新しい照合で残る |
    |---|---|---|---|---|---|
    | 1 | 11 秒 | 6 | 3 | 3 | 3 |
    | 2 | 28 秒 | 9 | 3 | 3 | 3 |
    | 3 | 18 秒 | 8 | 3 | 3 | 3 |

  - #9（同じ条件）では理由 3 か所のうち 1 か所しか残らなかった回が 2 回あった．今回は 3 回とも 3 か所残った
  - **効いたのはプロンプトの指示**．Gemini が why を transcript と同じ書き方で写すようになり，前の照合のままでも全部通った．新しい照合が拾った（書き方をそろえて通した）ものは 0 か所で，照合の効果はこの 3 回では出ていない．照合は，指示が守られなかった回の保険として残す（#9 で落ちた実際の文字列が通ることはテストで確かめた）
  - 残った why はどれも transcript の一部そのままで，言い換え・付け足しは無かった
  - ただし **transcript 自体が原本と違う回があった**．原本の余白のメモは「← √2も分数も消して整数だけにしたい」だが，1・3 回目は「√2も」が抜けて「分数も消して…」，2 回目は「ルートも分数も…」と書き起こした．why は transcript からの引用なので，照合はこれを捕まえられない．契約の README のとおり，本人が UI で承認・削除して直す前提にする
