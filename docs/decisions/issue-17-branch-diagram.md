# 分岐点の図は，同じ区間を1本の枠にまとめ，分かれた区間を左右2本に分けて縦に並べ，区間のあいだに「分岐点」「合流点」の線を引く（2026-11-08）

- 決めたこと:
  - 全員が提出したあと，問題の詳細ページに「分岐点の図」を出す（`web/src/ComparisonSection.tsx`）．最初は自分（左）と，自分以外で最初の参加者（右）．3人以上なら左右それぞれ選べる
  - 図（`web/src/BranchDiagram.tsx`）は CSS Grid の2列．`same` の区間は2列をまたぐ1つの枠（左右の what を並べる），`split` の区間は左右別々の枠．片方が空の `split` は点線だけ引く
  - 区間のあいだに SVG の線を引く．`same` → `split` は1本が2本に分かれる線と「分岐点」，`split` → `same` は2本が1本になる線と「合流点」，先頭が `split` なら「最初から分かれている」（`boundaryBefore`．README の定義どおり）
  - 保存では `a` が uid の小さい方なので，左に出す人が `b` なら区間の `a`・`b` を入れ替えて描く
  - 「同じことをした（AI の対応づけ）」と区間ごとに書き，図の上に「AI が対応づけた図で，正誤やどちらがよいかは表さない．違うと思ったら話し合ってほしい」と書く
  - `processing` のまま `updatedAt` から 6 分過ぎた組は `failed` と同じく「比べられませんでした」と出す（012 の申し送り．`StepsStatus` と同じ目安）
  - 画面の型は `web/src/comparisons.ts` に手で書いた（`server/src/contract.ts` と同じく，契約は `shared/schema/step-alignment.schema.json`）
- 理由:
  - 012 で区間の列にしたので，区間を上から順に並べれば「2本の道が分かれて合流する」形がそのまま描ける．位置の計算が要らず，ステップの文の長さが違っても枠が伸びるだけで崩れない
  - 線を SVG にしたのは，枠は HTML のままで読み上げ・折り返しが効き，線だけを見た目として足せるから（`aria-hidden`．「分岐点」「合流点」の文字は HTML で出す）
  - 自分を左にしたのは，自分の考えと比べて読むのが主な使い方だから
  - 「AI の対応づけ」と書くのは，「同じ／分かれた」も AI の提案で，最終判断は人がするため（設計原則）
- 捨てた案とその理由:
  - グラフ描画ライブラリ（React Flow・D3 など）: 依存が増える．区間が縦に並ぶだけなので Grid と線で足りる
  - 全体を1枚の SVG で描く: 日本語の折り返し・枠の高さを自分で計算することになる
  - 左右のステップを横に並べ，対応を線でつなぐ（対応表の形）: 「道が分かれて合流する」が見えにくく，ステップ数が違うと線が交差しやすい
  - 3人以上を1枚に重ねて描く: 区間は2人ずつなので，3人分の区間を合わせる決まりが無い
- 承知のうえの弱さ:
  - 「ここは違う」と人が言う入口（012 の申し送り）は文言だけで，ボタンや記録は無い．問いかけ・質問（#19）の形が決まってから足す
  - ステップは what だけを出す．why・元の場所（画像の枠・動画の時刻）は自分の解法の一覧（`StepList`）でしか見られない
  - 参加者の名前を保存していないので「参加者1・2…」（参加順）と出す
  - `failed` の組を作り直す口は無い（012 のまま）
  - 動作確認はエミュレータにデモデータを直接書いて行った（Gemini で作った本物の対応関係ではない）
