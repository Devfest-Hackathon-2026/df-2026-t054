# ステップへの質問は `problems/{problemId}/threads/{threadId}` に1つずつ置き，返信はその下の `replies` に置く．全員が提出したあとの参加者だけが読み書きでき，消せるのは自分が書いたものだけ（2026-11-08）

- 決めたこと:
  - Firestore のデータ構造（共有の契約）:
    ```
    problems/{problemId}/threads/{threadId}            ← 質問1つに1つ．ID は自動
      uid: string           ← 質問した人
      stepOwnerUid: string  ← 質問先のステップを持つ投稿の人（memberUids のどれか）
      stepId: string        ← steps/{stepOwnerUid} の thoughtSteps.steps[].id
      text: string          ← 1〜1000字
      createdAt: Timestamp  ← request.time
    problems/{problemId}/threads/{threadId}/replies/{replyId}   ← 返信1つに1つ．ID は自動
      uid: string
      text: string          ← 1〜1000字
      createdAt: Timestamp
    ```
  - ルール（`firebase/firestore.rules`．テストは `firebase/test/rules.test.ts`）:
    - 読む・書く: 全員が提出したあとの参加者（`canSeeOthers()`）
    - 書くとき: 項目はちょうど上のもの，`uid` は自分，`createdAt` は `request.time`，質問の `stepOwnerUid` は参加者，返信は親の質問があるときだけ
    - 書き直しはできない．消せるのは自分が書いたものだけ
  - 「時刻への質問」はステップへの質問で兼ねる．動画のステップは時刻の範囲を持ち，その下に質問が並ぶので，ステップの「▶ 再生」でその時刻を開ける
  - 画面: 思考ステップの一覧（自分のもの・ほかの参加者のもの）の各ステップの下に，質問・返信と「このステップに質問する」を出す（`StepListWithThreads` → `StepThreads` → `StepThread`）．書いた人は「参加者N（あなた）」で出す
  - 返信の付いた質問は，画面では「質問を消す」を出さない
  - 全員が提出したあと，「自分の解法」の見出しの下に「あなたのステップに質問が N 件あります」を出す（ほかの参加者からの質問だけ数える．`MyThreadsNotice`）．質問はステップ一覧の下のほうに出て気づきにくいため（レビューの指摘）
- 理由:
  - 質問をステップ（stepOwnerUid と stepId）に結び付けたのは，統合案の「質問が場所に結び付く」に合わせ，2人の組（comparisons）に関係なく1つのステップに集まるようにするため．#20 の answers は組ごとの AI の問いへの答えなので，別のコレクションにした
  - 質問と返信を分けたのは，ルールで「返信は質問がある所にだけ」を確かめられ，1つのドキュメントに配列で返信をためると同時に書いたときに消し合い，項目もルールで確かめにくいから
  - 書き直しを許さないのは，返信が付いたあとに質問の意味が変わると話がずれるから．消すのは書いた人が取り消せるよう許した（人が選んだ）
  - 全員が提出したあとだけにしたのは，提出前に他人のステップは見えず（011），自分のステップへの質問も他人にしか書けないから
  - 一覧の読み込みは `where('stepOwnerUid', '==', …)` だけにして並べ替えは画面でする．`orderBy` を別の項目に足すと複合インデックスが要り，`firestore.indexes.json` の管理が増えるため
- 捨てた案とその理由:
  - `comparisons/{pairId}/threads` の下に置く: #20 と並ぶが，3人以上だと同じステップへの質問が組ごとに分かれてしまう
  - 質問のドキュメントに `replies` 配列を持たせる: 読み込みは1回で済むが，同時に返信すると上書きし合い，ルールで配列の中身を確かめられない
  - 秒単位の時刻を質問に持たせる: ステップより細かく指せるが，入力の画面とルールが増える．ステップの時刻の範囲で足りると判断した（人が選んだ）
- 承知のうえの弱さ:
  - ルールでは返信の有無を確かめられないので，画面を通さなければ返信の付いた質問も消せる．そのときの返信は Firestore に残るが画面には出ない
  - ステップの ID が実在するかはルールで確かめない（steps のドキュメントは配列で，ルールで探せない）．画面はあるステップにしか欄を出さない
  - 出し直し（全員の提出前）でステップの ID が変わっても，質問は全員の提出後にしか書けないので，ずれは起きない
  - 書いた人の表示は「参加者N」．名前は保存していない（ほかの画面と同じ）
