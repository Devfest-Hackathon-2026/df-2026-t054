# 式変形のステップは，Gemini が式を写し，こちらが作った SymPy のコードを Gemini のコード実行で動かして確かめ，`steps/{uid}` の `mathChecks` に参考として保存する（2026-11-08）

- 決めたこと:
  - 形（新しい契約）: `shared/schema/math-checks.schema.json`．`{ schemaVersion, checks[], code }`．各確認は `{ stepId, before, after, result: 'same' | 'not_confirmed' | 'unparsed', detail }`
  - 流れ（`server/src/mathChecks.ts`．新しいトリガー `stepsToMathChecks`）:
    1. 思考ステップが `done` になったら，Gemini（構造化出力）に各ステップの `transcript` から「変形前の式 → 変形後の式」の組を SymPy の書き方で写させる．直さない・補わない．定義（〜とおく）や方程式・不等式を解く変形は含めない
    2. 組はコードで確かめる（ステップに無い id・空・200字超・英数字と `+-*/^()., !_` 以外の文字・属性の参照（`.` の直後の英字）・使えない名前・前後が同じ，を捨てる．10組まで）．使える名前は1文字の変数（`x`・`x1`・`x_1`）と，決めた数学の関数・定数・ギリシャ文字だけ
    3. こちらが SymPy のコードを組み立てる（`parse_expr` で読み，`simplify(before - after) == 0` か `equals(0) is True` なら `same`）．Gemini のコード実行（`tools: [{ codeExecution: {} }]`）に「一字も変えずに実行して」と渡す
    4. 返り値の `executableCode` がこちらのコードと同じとき（改行・行末の空白の違いは無視する）だけ，その直後の `codeExecutionResult` の出力を使う．Gemini の地の文は使わない．コードを実行しなかったら1回だけやり直す
  - Firestore のデータ構造（共有の契約．009 に2項目足す）:
    ```
    problems/{problemId}/steps/{uid}
      ...（009 のとおり）
      mathCheckStatus: 'processing' | 'done' | 'failed'   ← 無い = #22 より前の投稿
      mathChecks: MathChecks | null                       ← done のとき．形は shared/schema/math-checks.schema.json
      warnings: string[]                                  ← 「式変形の確認: 」で始まる警告を足す
    ```
  - ルールは変えない（`steps` は 009・011 のルールのまま．書くのはサーバーだけ）
  - 画面（`web/src/StepList.tsx`・`MathCheckList.tsx`・`MathCheckNote.tsx`）: 式変形のあるステップの下に「式の確認（参考）」として次の3つの文言のどれかを出す．`failed`・処理中は何も出さない
    - `same`: 「SymPy で計算すると同じ式になった」
    - `not_confirmed`: 「SymPy では同じ式だと確かめられなかった（違う式とは限らない）」
    - `unparsed`: 「式として読み取れず，確かめていない」
    - 一覧の下に，開いて読む断り書き（AI が写した式を SymPy で計算した参考．写し間違いもある．正しいかどうかは自分で確かめる）と，SymPy の出力・実行したコードを置く
- 理由:
  - 「AI に正誤を判定させない」ため，Gemini には式を写すことだけをさせ，同じ式かどうかは SymPy の計算の結果をそのまま使う．画面でも「正しい／誤り」とは書かない（3通りの文言は人が選んだ）
  - コードをこちらで組み立て，実行されたコードと突き合わせるのは，Gemini が結果を作れないようにするため．実際に，はじめのプロンプト（「一字も変えずに実行して」だけ）では `gemini-3.1-flash-lite` が6回中6回コードを実行せず，それらしい出力を文で書いた．突き合わせていたので，作られた出力は使われなかった．プロンプトに「コード実行ツールを必ず使う．出力を自分で予想して書かない」を足すと14回中14回，同じコードを実行した
  - 式を写す呼び出しと実行する呼び出しを分けたのは，1回目を構造化出力にして組をコードで確かめてから，2回目でこちらのコードだけを動かせるから
  - 式の文字を絞ったのは，式を Python のコードに埋め込むため（引用符・バックスラッシュ・改行を通さない）．コードは Gemini のサンドボックスで動き，こちらのサーバーでは動かない
  - 名前まで絞ったのは，`parse_expr` が中で `eval` するため．文字だけを絞った版では `print(chr(77)+…)`・`().__class__.__base__`・`x.subs(x, 2)` が通り，投稿に仕込んだ式を Gemini が写すと，`chr` で `MATHCHECK {…}` の行を作って結果を「同じ式」に見せかけられた（PR #69 のレビュー）．`__` と属性だけを弾く案は，`print(chr(…))` を防げないので採らなかった．あわせて，同じ組の出力行が2行以上あればその組は `unparsed` にする
  - `steps/{uid}` に足したのは，確認が投稿ごとに1回で済み，読める人も思考ステップと同じだから．ルールとテストを足さずに済む（人が選んだ）
  - 別のトリガーにしたのは，思考ステップの表示と比べる画面（`stepsToComparisons`）を確認の分だけ待たせないため
  - 失敗したら何も出さないのは，参考の情報で，無くても学習の流れは止まらないから
  - Issue の「Gemini のコード実行」に沿い，Python の実行環境をこちらで持たない（Cloud Run に Python を足すと構成とデプロイが増える）
- 捨てた案とその理由:
  - Gemini に SymPy のコードを書かせて実行させる: Gemini が書いたコードが本当に確かめているかを機械で確かめられない（`print("same")` と書けば済んでしまう）
  - Gemini に「同じ式か」を答えさせる: AI に正誤を判定させることになる
  - Cloud Run に Python と SymPy を置いて自分で実行する: 確実だが，`server/` が Node なので実行基盤とデプロイが1つ増える．Issue の指示とも違う
  - 新しいコレクション `problems/{id}/mathChecks/{uid}` に置く: ルールとテストを足す必要があり，PR が大きくなる
  - 一致したときだけ出す: 確かめられなかったことが分からず，すべて確かめて問題が無かったように見える
  - 契約を単独の PR に分ける: CLAUDE.md の決まりだが，人の判断で #19 と同じく1つの PR にまとめ，レビューで確かめてもらう
- 承知のうえの弱さ:
  - `before`・`after` は Gemini が写した式なので，写し間違えると，本人の変形とは別の式を確かめた結果になる．画面に写した式を出して照らし合わせられるようにし，断り書きにも書いた
  - 確かめるのは「式が同じ値の別の形に書き換えられたか」だけ．方程式・不等式の変形や，証明の文の筋道は確かめない（デモの素数の証明では式変形が無く，何も出ない）
  - `not_confirmed` には，誤った変形のほか，条件しだいで同じになる式（`sqrt(x**2)` → `x` など）や SymPy が簡単にしきれない式も入る．文言で「違う式とは限らない」と書いた
  - `not_confirmed` の詳細（`before - after` を簡単にしたもの）は，開いたときだけ出す．どこが違うかのヒントになりうるが，SymPy の計算の事実なので隠さない
  - プロンプトを足したあとも，コードを実行しない回がありうる．1回だけやり直し，それでもだめなら `failed` にして何も出さない
  - 本番のトリガーからの呼び出しはデプロイ後に確かめる．ローカルではエミュレータの Functions から本物の Gemini を呼んで，テキストの投稿で通した（下の出力例）
  - 使える名前の一覧に無い関数（`Sum`・`diff` など）を使った式は捨てるので，確かめられる式変形は限られる．必要になったら一覧に足す
  - 出し直しのたびに Gemini を最大3回（写す1回・実行1〜2回）多く呼ぶ
- 出力例（2026-11-08，`gemini-3.1-flash-lite`．エミュレータでテキストの投稿 `shared/schema/examples/algebra.sample.tex` を出した結果）:
  - 思考ステップは4つ（方針・`(x+1)^2` の展開・`(x-1)^2` の展開・引き算）．式変形は3組写された
  - `(x + 1)**2 → x**2 + 2*x + 1`: same / `(x - 1)**2 → x**2 - 2*x - 1`: not_confirmed（detail `2`）/ `(x**2 + 2*x + 1) - (x**2 - 2*x - 1) → 4*x + 2`: same
  - 素数の証明（`text.sample.json`）では，「M = n! + 1 とおく」を拾わず，組は0（`checks` は空）
  - `cd server && node scripts/try-math-checks.ts [サンプル]` で同じことを試せる
