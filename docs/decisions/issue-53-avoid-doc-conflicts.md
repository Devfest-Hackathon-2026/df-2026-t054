# 判断記録は Issue 番号で名前を付け，AI の使い方の記録は Issue ごとのファイルに分ける（2026-11-08）

- 決めたこと:
  - 判断記録の新しいファイルは `docs/decisions/issue-<Issue番号>-短い説明.md`．既存の `001`〜`013` は名前を変えない
  - AI の使い方の新しい行は `docs/ai-usage/issue-<Issue番号>.md` に書く（列は今の表と同じ．書き方は `docs/ai-usage/README.md`）．`docs/ai-usage.md` は #53 より前の分として残し，行を足さない
  - 提出書類を書くときは，`docs/ai-usage.md` と `docs/ai-usage/` を合わせて読む
- 理由:
  - 3 桁の連番は，並行する PR が同じ「次の番号」を取り合う．010（#44 と #46）・012（#47 と #48）がぶつかり，そのたびに番号を付け直した．Issue 番号はブランチを切る時点で決まっていて重ならないので，誰とも調整せずに名前が決まる．ブランチ名（`<種類>/<Issue番号>-…`）とも対応する
  - `docs/ai-usage.md` は全員が表の末尾に 1 行足すので，ほぼすべての PR が衝突した（#47 は 3 回解消した）．PR ごとに別のファイルなら同じ場所を触らない
- 捨てた案とその理由:
  - `.gitattributes` に `docs/ai-usage.md merge=union` を書く: 手元の `git merge` では両方の行が残るが，GitHub の PR のマージと衝突の判定はこの設定を使わない（GitHub Community の議論・サポートの回答）．マージボタンで衝突が残る
  - 判断記録を日付で名前を付ける（`2026-11-08-…`）: 重なりにくいが，Issue とのつながりが名前から分からない
  - 連番のまま，マージする人が直前に番号を振る: 名前の形は変わらないが，マージのたびに手作業が要り，本文やほかの Issue から参照している名前も変わる
  - AI の使い方を PR の本文に書き，最後に 1 人がまとめる: PR は ai-usage を触らずに済むが，最後のまとめを忘れると必須記入が抜ける．ファイルなら書いた時点でリポジトリに残る
  - 既存の `001`〜`013` も新しい付け方に名前を変える: CLAUDE.md・判断記録どうし・Issue から名前で参照しているので，リンクが切れる
- 承知のうえの弱さ:
  - 判断記録が「以前の連番」と「Issue 番号」の 2 種類になる．`ls` では `001`〜`013` の後に `issue-…` が並び，`issue-…` どうしは文字の順（`issue-16` が `issue-9` より前）になる
  - 1 つの Issue で判断が 2 つ以上あるときは，説明の部分で分ける（同じ PR の中なので衝突しない）
