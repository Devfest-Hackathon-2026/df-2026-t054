# 分岐点と「なぜ」が空のステップへの AI の問いかけは，対応関係を作った直後に Gemini で作り，`comparisons/{uidA}_{uidB}` の `questions` に保存する（2026-11-08）

- 決めたこと:
  - 形（新しい契約）: `shared/schema/step-questions.schema.json`．`{ schemaVersion, questions[] }` で，各問いは `{ side: 'a' | 'b', stepId, kind: 'branch' | 'missing_why', text, by: 'ai' | 'template' }`
  - 問う対象はコード（`server/src/questions.ts` の `questionTargets`）が決める
    - `branch`（分岐点）: 対応関係の `split` の区間で，その側の最初のステップ．`why` があっても問う
    - `missing_why`: それ以外で `why` が `null` のステップ
  - Gemini には対象ごとの問いの文だけを書かせる．`responseJsonSchema` で `target`（`"a:s2"` の形）を対象のキーの `enum` に絞る
  - Gemini に渡すのは問題文と各ステップの `id`・`what`，対象の一覧（分岐点では，もう1人が同じ区間でしたことの `what` をコードで添える）．`why`・`transcript`・元の場所は渡さない
  - プロンプトで「問うだけ．答え・理由・ヒントを書かない．理由の候補を挙げて確かめる問い（〜だからですか？）にしない．評価しない」と指示する
  - 返り値はコード（`normalizeQuestions`）で確かめる．無い・「？」で終わらない・120字を超える・改行がある・理由を一から問う疑問詞（なぜ・どうして・何・どの・どう・どんな）を含まない・「〜だから／ので／のにですか？」の形・評価の言葉を含む問いは捨て，その対象は決まった文（`by: 'template'`）にする．`validateStepQuestions` で確かめてから保存する
  - Gemini の呼び出し自体が失敗したら，すべて決まった文にする（対応関係はできているので，比べる画面を止めない）．警告は `warnings` に足す
  - 作るタイミング: `stepsToComparisons` の `compare` の中で，対応関係ができた直後（同じトランザクション外の続き）．Gemini を2回目に呼ぶ
  - Firestore のデータ構造（共有の契約．012 に1項目足す）:
    ```
    problems/{problemId}/comparisons/{uidA}_{uidB}
      ...（012 のとおり）
      questions: StepQuestions | null   ← done のとき．形は shared/schema/step-questions.schema.json．side の a が uidA，b が uidB
      warnings: string[]                ← 対応関係と問いかけの両方の警告
    ```
  - ルールは変えない（`comparisons` は 012 のルールのまま．全員が提出したあとの参加者が読める．書くのはサーバーだけ）
- 理由:
  - 対象をコードで決めたのは，「分岐点」の定義が対応関係（012）から機械的に決まり，`why` が空かも契約から分かるので，AI に選ばせる理由が無いから．Gemini には文を書く部分だけを任せる（012 と同じく「AI の出力はコードで直して契約に合わせる」方針）
  - `comparisons` に入れたのは，分岐点の問いが「誰と比べたか」で決まり，組ごとのドキュメントにすでに対応関係があるから．ルールとテストを足さずに済む（人が選んだ）
  - `why`・`transcript` を渡さないのは，本人の理由（引用・書き込み）を AI が言い換えて問いの中に書いてしまうのを防ぐため．問いに要るのは「何をしたか」だけ
  - 「〜だからですか？」を禁じたのは，理由の候補を挙げると，本人が自分で考える前に AI が理由を書いたのと同じになるから
  - 疑問詞を含むことを条件にしたのは，「〜と考えたのですか？」「〜と思ったのでしょうか？」のようなはい／いいえで答える問いは，ほぼ必ず理由の候補を中に含むから．捨てる言葉を並べるより漏れが少ない．「何のためですか」は目的を一から問う良い問いなので，「ため」は目安に入れない（PR #60 のレビューで，表の形の例を挙げて指摘された．テストに入れた）
  - 決まった文に戻すのは，問いが無いと #20 で理由を書く入口が無くなるから．決まった文なら答えを含みようがない
  - 分岐点では `why` があっても問うのは，投稿の中の理由は「なぜその方法か」であって，もう1人の道と比べた「なぜこちらか」ではないため（人が「分岐点＋why が空の全ステップ」を選んだ）
- 捨てた案とその理由:
  - 新しいコレクション `problems/{problemId}/questions/{id}` に1問1ドキュメントで置く: #20・#21 で返信や既読を足しやすいが，ルールとテストの追加が要り PR が大きくなる．必要になったら #20 で移す
  - 投稿ごと（`steps/{uid}`）に「なぜ」が空の問いを作る: 分岐点の問いは組ごとにしか作れず，2か所に分かれる．全員がそろうまで比べる画面は出ないので，早く作っても使われない
  - 対応関係と同じ1回の呼び出しで問いも作らせる: 分岐点が決まる前に問いを書かせることになり，捨てた組の問いが残る．1回目の出力を確かめてから問う方が安全
  - 決まった文だけにする（AI を使わない）: 「何をしたか」に触れない問いは答えにくい．AI に書かせつつ，使えないものだけ決まった文にする
  - 問いの良し悪しを Gemini にもう1回確かめさせる: 呼び出しが増える．目安の言葉とプロンプトで足りるかを先に見る
- 承知のうえの弱さ:
  - 答えや理由を含む問いを捨てる目安は言葉の一致なので漏れうる．たとえば疑問詞が what の引用の中にあるだけのはい／いいえの問い（「どの pi で割っても1余ることを確かめたのですか？」）は残る．画面では「AI の問いかけ」と分かるように出し，本人が無視できるようにする
  - Gemini の実際の出力は，契約のサンプル（image と video）1組で1回確かめただけ（下の出力例）．本番のトリガーからの呼び出しはデプロイ後に確かめる
  - 分岐点でない問いが「〜する必要があると考えたのですか？」のように，必要だったことを前提にした言い方になることがある．理由は書いていないので目安では捨てない
  - 3人以上だと，同じステップに組の数だけ問いが付く
  - 問いかけだけを作り直す仕組みは無い（012 の対応関係と同じ）
- 出力例（2026-11-08，`gemini-3.1-flash-lite`，`cd server && node scripts/try-questions.ts` で契約のサンプル image（a）と video（b）に1回投げた結果）:
  - 8問すべて Gemini の問いがそのまま使われた（`by: "ai"`，`warnings` は空）．35〜60字で，どれも「なぜ」で一から問う形．答え・理由の候補・評価は含まれていない
  - 分岐点（branch）の問いは，もう1人がしたこと（相手の what）に触れてから「なぜこちらを選んだか」を問う形になった
    | 対象 | kind | 問い |
    |---|---|---|
    | a:s1 | branch | もう1人は方針を立てることから始めましたが、あなたはなぜ素数が有限個であると仮定して並べる方法を選んだのですか？ |
    | a:s2 | missing_why | なぜすべての素数の積に1を足した数Nを作るという手順をとったのですか？ |
    | a:s3 | missing_why | なぜNをどの素数で割っても1余ることを確かめる必要があると考えたのですか？ |
    | a:s4 | branch | もう1人は集まりに入らない素数の存在から結論を導きましたが、あなたはなぜ仮定との矛盾を導く方法を選んだのですか？ |
    | b:s1 | branch | もう1人は素数が有限個だと仮定して並べましたが、あなたはなぜ有限個の集まりから新しい素数を見つける方針を立てたのですか？ |
    | b:s2 | missing_why | なぜ選んだ素数をすべて掛けて1を足した数Nを作るという手順をとったのですか？ |
    | b:s3 | missing_why | なぜNの素因数を1つ取り出し、それが選んだ素数とは違うことを示す必要があると考えたのですか？ |
    | b:s4 | branch | もう1人は仮定との矛盾から結論を導きましたが、あなたはなぜ集まりに入らない素数の存在から結論を導く方法を選んだのですか？ |
  - 手で書いた形の例は `shared/schema/examples/questions.image-video.sample.json`
