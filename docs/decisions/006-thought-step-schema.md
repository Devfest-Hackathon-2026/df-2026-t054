# 思考ステップは「what・why（null 可）・source（画像の範囲・テキストの行・動画の時刻）」の JSON にする（2026-11-06）

- 決めたこと:
  - スキーマは `shared/schema/thought-steps.schema.json`（JSON Schema draft 2020-12）．1投稿 = `{ schemaVersion, steps[] }`，各ステップは `id`・`what`・`why`・`transcript`（任意）・`source`
  - `why` は `null` を許し，値があるときは `{ text, by }` にして「誰の言葉か」を残す．`by` は `post_quote`（投稿の中で本人が書いた・話した理由の引用）か `author`（本人がアプリで書き込んだ）の2つだけ．AI が推測した理由を表す値は作らない
  - `post_quote` は，同じステップの `transcript` に `why.text` がそのまま含まれるときだけ認める．UI では本人が承認・削除できるようにする（レビューで条件として決めた）
  - `source` は `kind` で分ける．画像は `imageIndex` ＋ `box2d: [ymin, xmin, ymax, xmax]`（0〜1000 の整数），テキスト（LaTeX・コード）は `lineStart`・`lineEnd`（1 始まりの行番号），動画は `startSec`・`endSec`（秒）
  - スキーマで表せない決まり（`id` の重複なし，範囲の大小，動画の長さ以下，`post_quote` の条件）は README に表で並べ，使う側で確かめる
- 理由:
  - 統合案4章「各ステップは何をしたか・なぜ・元の場所を持つ」「なぜが空なら AI は問いかけるだけ」をそのまま形にした．`by` があれば，UI で「本人の言葉」と示せ，AI が理由を書いていないことを審査でも説明できる（テーマ "Own the Why"）
  - `box2d` は Gemini が bounding box を返すときの形と同じなので，画像 PoC（#8）で変換が要らず，Gemini が得意な形のまま受け取れる
  - 動画の時刻を秒にしたのは，比較 UI（#18）が `<video>.currentTime` にそのまま渡せるから
  - テキストを行番号にしたのは，Gemini に行番号付きで渡して番号で答えさせれば文字数を数えさせるより間違えにくく，表示側も本文を改行で分けるだけで印を付けられるから（#8 の PoC 側からの提案）
  - `post_quote` に条件を付けたのは，`transcript` も AI の書き起こしで誤りうるため（#7 で「背理法」が「入り法」になった）．文字列の照合だけでは本人の言葉だと保証できず，最後は本人が確かめる
  - 画像と動画で `what` / `why` を共通にし，違いを `source` だけに閉じ込めたので，比較・分岐点の処理は媒体を気にせず書ける
- 捨てた案とその理由:
  - `why` を常に空で作り，理由は必ずアプリで本人に書かせる: 原則には最も忠実だが，動画では本人が話の中で理由を言うことが多く，同じことを打ち直させるのは UX が悪い．引用に限って抜き出してよいことにし，`by` で区別する
  - `why` を単なる文字列にする: AI の言い換えと本人の言葉が区別できなくなる
  - 範囲を `{ x, y, width, height }`（0〜1 の小数）にする: 表示側は少し楽だが，Gemini の出力から毎回変換が要り，PoC で座標ずれの原因を切り分けにくい
  - 動画の時刻を `"MM:SS"` の文字列にする: Gemini には答えさせやすいが，保存・比較・再生のたびに変換が要る．必要なら PoC 側で秒に直す
  - 投稿全体に `media: "image" | "video"` を持たせる: ステップの `source.kind` と二重になり食い違いうる
  - テキストの範囲を文字の位置（`startOffset`/`endOffset`）や引用した文字列で示す: LLM は文字数を数えるのが苦手でずれやすい．引用は同じ式が2回出ると場所が決まらない
  - LaTeX を画像に描いて `imageSource` を使う: 描画の処理が要り，本文のテキストとも対応しなくなる
  - `post_quote` のとき `transcript` を必須にする決まりを `if`/`then` でスキーマに書く: 保存時の検証は楽になるが，#7 で確かめた「Gemini の `responseJsonSchema` にそのまま渡せる」が崩れるおそれがある．使う側の確認に回した
- 未決: 1投稿に複数テキストがあるとき，分岐点・質問の形，Firestore の保存場所（別の契約）
