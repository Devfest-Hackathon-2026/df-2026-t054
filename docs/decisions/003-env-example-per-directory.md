# 環境変数の一覧 `.env.example` はディレクトリごとに置く（2026-11-06）

- 決めたこと:
  - `web/.env.example` と `server/.env.example` を分けて置く．リポジトリ直下には置かない
  - 載せるのは名前と1行の説明だけで，値は書かない．載せる範囲は近く使う分（Firebase の Web 設定，server の URL，Vertex AI 用のプロジェクト・リージョン・モデル・バケット）
  - `server/` の認証はサービスアカウント鍵を使わず，ローカルは ADC（`gcloud auth application-default login`），Cloud Run はサービスのサービスアカウントにする．そのため鍵のパスの変数は置かない
- 理由:
  - Vite は既定で `web/` 直下の `.env` しか読まない．ディレクトリごとに置けば `vite.config.ts` を変えずに済む
  - `VITE_` 付きの変数はビルドに埋め込まれて公開される．`server/` の変数と同じファイルにすると，秘密の値をうっかり `VITE_` 側に書く事故が起きやすい
- 捨てた案とその理由:
  - 直下に1つ置き，`vite.config.ts` に `envDir: '..'` を足す（計画書の仮の構成）: 公開される変数と秘密の変数が1ファイルに混ざる．Vite の設定も変える必要がある
  - 今使っている変数だけ載せる: まだどのコードも環境変数を読んでおらず，空のファイルになって役に立たない
