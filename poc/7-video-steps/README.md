# PoC #7: 説明動画 → 思考ステップ＋時刻（Cloud Storage 経由・Vertex AI）

説明動画を Cloud Storage に上げ，Vertex AI の Gemini に `gs://` の URI と `responseJsonSchema` を渡して，
思考ステップの契約（[`shared/schema/thought-steps.schema.json`](../../shared/schema/thought-steps.schema.json)）の形の JSON を取り出す．

> **PoC のコードは本番に流用しない**（`docs/regulations.md`）．#14 で本番に組み込むときは，ここで分かったことを参考に書き直す．

## 動かし方

前提: Node 24 以上，`gcloud` CLI（ログイン済み），ADC（`gcloud auth application-default login`）．
合成動画を作るときだけ macOS（`say`・`swift`）と `ffmpeg` が要る．

```bash
cd poc/7-video-steps
npm install
cp .env.example .env              # POC_GCS_BUCKET などを書く
npm run make-video                # samples/synthetic-primes.mp4 と .truth.json を作る（任意）
npm start -- samples/synthetic-primes.mp4 --truth samples/synthetic-primes.truth.json
```

| オプション | 意味 |
|---|---|
| 1つ目の引数 | ローカルの動画（上げてから使う）か `gs://...`（上げずに使う） |
| `--model` | 既定は `.env` の `GEMINI_MODEL`（無ければ `gemini-3.1-flash-lite`） |
| `--mode contract` | 既定．契約のスキーマをそのまま `responseJsonSchema` に渡す（時刻は秒で返る） |
| `--mode mmss` | 時刻を `"MM:SS"` で答えさせ，`id`・`source.kind`・`why.by` はコードで付ける |
| `--truth` | 正解の区間．各正解ステップの開始時刻と，いちばん近い予測の開始時刻の差を出す．`endSec` が動画の長さを超えたら警告する |
| `--fps` / `--media-resolution low\|medium\|high` / `--thinking-budget` | 動画のサンプリングと思考の量（費用の調整用．今回は既定のまま） |

実際に返った例（flash-lite・contract）は `samples/synthetic-primes.result.example.json`．
結果は `out/<動画>.<モデル>.<モード>.<時刻>.steps.json`（契約の形）と `.meta.json`（処理時間・トークン・費用・警告・生の返り値）に保存される．
`npm run validate -- out/*.steps.json` で契約に合っているか確かめられる（`ajv` などを足さず，`src/contract.ts` で手書きで検証している）．

### 原則を守るための仕掛け

- AI が書けるのは `what`・`transcript`・**理由の引用**だけ．`why.by` は常にコードが `post_quote` を付ける（AI が `author` を返したら捨てる）
- `why.text` が `transcript` の中にそのまま無ければ `null` にして警告を出す（AI の言い換え・推測を落とす）
- プロンプトで「正誤を判断しない」「評価を書かない」「理由を推測しない」を指示している

## 試した動画

`samples/synthetic-primes.mp4`（69 秒，1.0 MB）．`scripts/make-synthetic-video.sh` が台本 `samples/synthetic-primes.script.json` から作る．
板書の画像を `swift` で描き，`say`（Kyoko）で読み上げた合成動画．内容は「素数が無限にあること」（統合案6章のデモと同じ題材）で，チームが書いた文章だけを使っている．
区間ごとの長さが分かるので，正解の開始時刻（`samples/synthetic-primes.truth.json`）と比べられる．
s1 だけ話の中で理由（「背理法で矛盾を出すより…分かりやすいと思ったので」）を言い，ほかのステップでは言わない．最初と最後の挨拶はステップにならないのが正解．

**まだ試していないこと: 実際に人が撮った説明動画（手書き・話し言葉・雑音・1〜5 分）**．合成動画は字がはっきりしていて話も台本どおりなので，精度は実際より良く出ているはず．

## 結果（2026-11-06〜07）

すべて Vertex AI（location `global`），`temperature: 0`，fps・解像度は既定．費用は `src/pricing.ts` の単価（2026-11-06 に公式の料金ページで確認）から出した目安．
第一候補の gemini-3.1-flash-lite は，各モードを **3 回ずつ**実行した（レビューの指摘で 1 回ずつから増やした）．

| モデル | モード | 回 | 生成時間 | 費用の目安（1 回） | ステップ数 | 開始時刻のずれ（平均，各回） | `endSec` が動画（69 秒）を超えた | why |
|---|---|---|---|---|---|---|---|---|
| gemini-3.1-flash-lite | **contract** | 3 | 4.2〜5.1 秒 | $0.0033（約 0.5 円） | 4 / 4 / 4 ✓ | **0.10 / 0.35 / 0.10 秒** | **3 回とも**（104〜104.5 秒） | 方針のステップだけ引用 ✓（3 回とも） |
| gemini-3.1-flash-lite | mmss | 3 | 3.7〜11.5 秒 | $0.0029（約 0.5 円） | **5 / 5** / 4（2 回は挨拶もステップにした） | 0.76 / 0.76 / 0.31 秒 | なし | 方針のステップだけ引用 ✓（3 回とも） |
| gemini-3.8-flash | mmss | 1 | 10.6 秒 | $0.0099（約 1.5 円） | 4 ✓ | 0.85 秒 | なし | 方針のステップだけ引用 ✓ |

- すべての回で契約に合う JSON が返り，**全ステップに開始時刻がある**．`why` はどの回も本人が理由を話した「方針」のステップだけが引用で，ほかは `null`（推測で埋めなかった）
- contract の 3 回はほぼ同じ結果（`temperature: 0`）．mmss は同じ条件でもステップの区切りが 2 通りに分かれた
- 入力トークンの内訳（69 秒）: 映像 約 4,550（1 秒 1 フレーム × 約 66），音声 約 1,700，プロンプト 約 570（contract はスキーマが長いので 約 1,230）．**1 秒あたり約 90 トークン**
- アップロード（1.0 MB）は 2.3〜2.6 秒．生成時間は 4〜21 秒とばらつく（同じ条件で 3 倍違うことがあった）

### 分かったこと

1. **契約のスキーマは `responseJsonSchema` にそのまま渡せた**（`$schema`・`$id`・`$defs`/`$ref`・`anyOf`・`const`・`pattern` を含んだまま 400 にならない）．`shared/schema/README.md` の「通らなければ取り除いた版を作る」は不要だった
2. **時刻は秒で答えさせる方がよい**: contract（秒）は 0.5 秒刻みで返り，開始のずれは平均 0.1〜0.35 秒．`MM:SS` は整数秒になり，0.3〜0.8 秒ずれた．ただし contract では**最後のステップの `endSec` が 3 回とも 104 秒前後（動画は 69 秒）**になった．本番では動画の長さで `endSec` を切り詰める（Gemini は動画の長さを返さないので，アップロード時にメタデータとして持っておく）
3. **mmss の方が指示を守らない**: mmss では 3 回中 2 回，挨拶（0〜5 秒）を 1 ステップにした．contract では 3 回とも守った（モデルの差ではなくスキーマの書き方の差の可能性があるが，1 本の合成動画では切り分けられない）
4. `gemini-2.5-flash` は，このプロジェクトでは `global` で 404（モデル一覧には出るが使えない）．新しいプロジェクトからは古いモデルを使えないものとして，3.x 系から選ぶ
5. 書き起こしの誤り: contract の 1 回目で「背理法」を「入り法」と書いた（その回は動画の作り方に不具合があった）．`why` の引用は `transcript` からの抜き出しなので，書き起こしの誤りもそのまま引用に入る．UI で「AI の書き起こし」と示し，本人が直せるようにした方がよい

### 費用の見積もり

1 秒 ≒ 90 トークン（映像 約 66 ＋ 音声 約 25）として，**5 分の動画 1 本**で:

| モデル | 入力 | 出力（思考込み，約 2,000 と仮定） | 合計 |
|---|---|---|---|
| gemini-3.1-flash-lite（映像 $0.25 / 音声 $0.50 / 出力 $1.50） | 約 $0.009 | 約 $0.003 | **約 $0.012（約 2 円）** |
| gemini-3.8-flash（入力 $0.75 / 出力 $3.75，2026 年末までの導入価格） | 約 $0.020 | 約 $0.008 | **約 $0.028（約 4 円）** |

クレジット $20 で 700〜1,600 本ほど．デモ・開発の範囲なら費用は問題にならない．
この PoC 全体（不具合のあった動画での回を含む 11 回）で使ったのは約 $0.05．

### #9（比較メモ）・#14（組み込み）への申し送り

- モデルは **gemini-3.1-flash-lite を第一候補**，挨拶をステップにする・区切りがおかしいなどが実際の動画で目立てば gemini-3.8-flash にする
- 時刻は秒で答えさせ（この PoC の既定も contract にした），`endSec` は動画の長さで切り詰める．`id` は返り値ではなくコードで振り直すと安全（今回は崩れなかった）
- **`why` の機械的な確認は「transcript に含まれているか」だけ**．理由ではない一文（例: 「これを N と置きます」）を抜き出しても通るし，transcript 自体も AI の書き起こし．本番では UI で「AI が抜き出した本人の言葉」と示し，**本人が承認・削除してから `why` として扱う**ことを前提にする（#31 のレビューでも同じ指摘）
- `src/contract.ts` の手書きの検証は，#31 でマージされた契約（`image` / `video` / `text`）と「使う側で確かめる決まり」に合わせてある．契約が変わるたびに手で合わせる必要があるので，本番（#14）では手書きをやめ，スキーマのファイルで検証する方がずれない
- Cloud Storage は PoC 用バケット `gdgoc-hackathon-513704-poc`（asia-northeast1，1 日で自動削除）を使った．本番では Firebase Storage のバケットの `gs://` をそのまま渡せる見込み
- 処理は 5〜20 秒かかるので，投稿時に同期で待たせず，Storage へのアップロードをトリガーにして裏で処理する（#14 の計画どおり）
- 実際の手書き説明動画で 1 回は試す（#23 のデモ動画ができたら）
